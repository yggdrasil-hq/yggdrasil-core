Wireframe · maps to /projects/:projectId/tests/:testId (web/app/projects/[projectId]/tests/[testId]/page.tsx → web/components/tests/test-detail-client.tsx). The run history is built (ADR 026 item 6, issue #16) and the file below now shows it; this note used to say the Test type had "no pass/fail history yet", which stopped being true when the run-history view shipped — corrected by issue #33. What the history actually is, because it is easy to confuse with the feature page's Testing tab: this is the project-level standalone Testing product — how one scheduled suite has behaved over time — not ADR 015's per-feature Testing stage, which asks whether one feature branch passed before review. The two share the report schema and nothing else. Every row is real data from the run's report plus its job row; the expanded row is the one place the failure artefacts are reachable (report summary, failing test names, per-step results, and the screen recording ADR 029 collects), which is why one is shown open. "Changes saved" below is the post-save state, shown here for reference, not conditional. Not mocked: the empty history (which reads differently for a paused test than for one that has never run, and says so), the "Showing the 25 most recent of N runs" truncation footnote, and the expanded row's "no report" branch — a run shown as failing while reporting nothing, which is a real and visible state rather than an edge case. Proposed IA rework: sidebar/topbar per /projects/:projectId; breadcrumb replaces the old "← Back to tests" link
