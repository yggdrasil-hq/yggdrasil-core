Corrected (issue #81) — this note previously said the feature had "no grounding anywhere: no ADR, no job kind, no skill, and no contract-tool event". All four of those now exist, so the note was describing a proposal as unbuilt long after it shipped: ADR 015 items 13–16 define the job kind, its read-only container tier, its inputs and its two transitions; agentic_review is a real job kind; the skill and image exist under agent-images/agentic_review/; and the shared contract extension's submit_review tool carries the verdict. A read endpoint (GET /projects/:id/features/:id/agentic-review) now serves the stored verdict to this page. What remains true is the empty state shown below: a review only exists once Testing passes. The Approved / Changes-requested subview was removed (issue #74). It was a radio-driven tab pair and could not work: a review carries exactly one verdict, so the control had no second category to select and its state was read by nothing but itself. Its replacement — filtering by blocking vs. non-blocking — was considered and rejected too, because the review payload carries no per-finding blocking flag, so every finding would have defaulted to blocking and the filter would have worked only against mock data. Both verdict shapes are still shown below, stacked rather than switched, because seeing both is the point of a design reference. Still a mock: the verdict, the file locations and the review comments are invented.
