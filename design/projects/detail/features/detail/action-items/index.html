Wireframe · maps to /projects/:projectId/features/:featureId/action-items — an entirely new route/concept, not in any ADR. Per the user's spec, spec_grill can now return action items alongside the ADR, and implementation can't start until every item is resolved. Grounding varies per item type, shown below: env var access and new env var requests plausibly extend project_secrets (job-dispatch.md already has the API decrypting and injecting per-project secrets into job pods — asking for one by name is a small step from that, not a big one). Move to design_grill extends ADR 014, but that ADR describes design sessions as freestanding (name + description, own PR) with no feature-linked entry/exit — treat that link as new. New subtask feature is the least grounded: ADR 002 has no parent/child relationship between features and no "blocked on another feature merging" state at all — this is a genuinely new dependency model, shown below via a linked feature that blocks this one until it merges. Test request is the most grounded — Tests are already a first-class per-project concept with their own create/detail pages; this just proposes spec_grill being able to ask for one.
