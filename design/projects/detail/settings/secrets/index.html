Wireframe · maps to /projects/:projectId/settings/secrets — split out of the old single-page settings, see General's design-note for the IA rework itself. The underlying concept is real — job-dispatch.md already has the API decrypting project_secrets server-side and injecting them as pod env vars for every job kind — this is the first UI for managing that table, which doesn't exist anywhere in web/ today. The "inherited from org" scope tag and Organization Settings → Secrets are new, modeled after the same org-owns/project-inherits pattern already proposed for Providers & Models — not grounded beyond that precedent. The link from STRIPE_WEBHOOK_SECRET back to a feature's Action Items is illustrative of the loop: spec_grill can ask for a secret, an admin fulfills it here, and the action item resolves.
