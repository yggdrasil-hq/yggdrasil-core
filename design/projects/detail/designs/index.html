Wireframe · maps to /projects/:projectId/designs (web/app/projects/[projectId]/designs/page.tsx → web/components/designs/designs-index-client.tsx). Added by issue #33 — the browse and re-open flows shipped with ADR 020 item 6 and had no reference at all (there was no design/designs/ tree in any form). Built and real: the filter pills, the search box, the per-row actions and the expandable details all exist. Two things to know before reading it as IA: the page is project-scoped, not a top-level /designs — a design belongs to one project's repository, so it lives under /projects/detail/designs/ like the other project surfaces. And the sidebar's Designs item is conditional: the shipped sidebar renders it only when the project is ready and hasDesignSurface (set by project_init's answer, ADR 014) — a project with no design surface never sees this route. Rows are sample data. The mockup itself is deliberately not rendered here: ADR 020 item 2 makes the repo the source of truth for the artifact, so this page is an index over the designs table and the mockup is viewed through the design's draft PR. The empty state ("No designs yet", with its honesty note that folders committed by hand are not listed) and the "No designs match this filter" state are not mocked.
