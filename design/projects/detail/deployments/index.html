Wireframe · maps to /projects/:projectId/deployments — a new route/page, no equivalent exists in web/ today. Maturity varies sharply by row, on purpose — don't read all four as equally real: Production is the only one that's actually built (Helm-managed always-on deployment, auto-deploy-on-merge via the webhook in ADR 013, domain pattern <project-slug>.apps.<domain> per ADR 003). Preview is "designed in ADR 003 but not implemented in orchestrator/ — no preview/temporary-deployment code exists" (roadmap/phases.md, Phase 2) — the whole ephemeral-tunnel-per-job mechanism this row implies is still just a spec, domain pattern <project-slug>-<kind>-<id>.preview.<domain> also from ADR 003. Staging is the least grounded of the three — it isn't decided at all, it's explicitly open-questions.md #9: "likely needs a staging branch + staging deployment gate before promoting to primary," listed as unresolved. Filter pills are inert. Deployed timestamps, URLs, and PR/job references are invented for the mockup.
