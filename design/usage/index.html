Wireframe · maps to /usage (web/app/usage/page.tsx → components/usage/usage-page-client.tsx). Built, and rendering measured data — corrected by issue #50, which found this note still describing the concept as untracked. What shipped: ADR 023 captures a token/cost/duration row per job (job_usage, migration 036), recording the resolved model, its provider, and the model-config tier that supplied it, and this page reads it. So the "assumes the API/Orchestrator logs a token count per job" sentence below is now simply true, and roadmap/phases.md's "token budgets" is a cap rather than reporting (ADR 030, and the two /allocations/* pages). The mock's numbers and percentages are still invented. Two figures here were deliberately not shipped, and that is the one substantive difference between this wireframe and the page: "% of limit" and "resets in N days" are unknowable — providers are bring-your-own-key and org-managed (per /settings/organization), so a reset date is the provider's own billing cycle, observable only if that provider's API happens to report it, and Yggdrasil neither bills nor owns a quota. The real page omits both and carries a metering notice saying so (ADR 023 item 17) rather than inventing them, so treat those two elements below as the mock's, not the product's. Project-level and account-level (user) versions of this page show the same providers scoped down to that project's/that user's share of consumption — see their own design-notes for how the three levels relate (org is the authoritative quota view; project and user are contribution slices of it, not separate quotas).
