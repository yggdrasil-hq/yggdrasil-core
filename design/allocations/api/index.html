Wireframe · maps to /allocations/api — a new route/page, no equivalent exists in web/ today. Org-admin-only in concept, same as /allocations/infra. Two different things are bundled on this page, with different grounding: (1) which providers a project may draw from — today every org-connected provider (/settings/organization → Providers & Models) is usable by every project with no restriction mechanism at all, so the on/off pills here are a proposed capability, not a real one. (2) a monthly token cap per project — this is what roadmap/phases.md Phase 4 lists as unbuilt "token budgets," a spending cap, distinct from the consumption reporting already mocked on /usage. Providers stay bring-your-own-key and org-owned either way (see the Usage page's design-note) — a cap here would throttle a project's draw against the org's own key, not create a separate quota. Nothing on this page is wired up; pill states and "Save changes" are inert.
