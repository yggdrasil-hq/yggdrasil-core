Wireframe · maps to /allocations/infra — a new route/page, no equivalent exists in web/ today. Org-admin-only in concept (same admin-vs-member split as /settings/organization's Providers & Models section), though this wireframe doesn't gate nav visibility by role — none of the top-level pages do that yet, only that one settings section has an explicit "Viewing as" toggle. What's grounded: ADR 003 §5–6 already establishes one Kubernetes namespace per project as the isolation unit, which is exactly the natural scope for a per-namespace ResourceQuota/LimitRange — this page is what configuring that would look like. What's not: ADR 003 never specifies real CPU/memory numbers (same caveat as the per-job-kind table on /infrastructure, which this page complements rather than replaces — that one shows read-only defaults by job kind, this one is per-project caps, editable by an admin), and there's no decided mechanism for the Orchestrator to actually enforce or report against limits set here. Nothing on this page is wired up; "Save changes" is inert.
