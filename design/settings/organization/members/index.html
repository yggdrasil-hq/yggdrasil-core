Introduces a new Organization/Membership/Role data model that ADR 002 explicitly deferred ("Team RBAC and multi-user project permissions (Phase 2)" — see ADR 002 follow-ups, and roadmap/phases.md: "RBAC, team invitations — not started, no team/org entity exists yet"). This wireframe treats projects as belonging to an org (not directly to owner_user_id as ADR 002 currently has it) — that's the load-bearing assumption behind this entire Settings group and needs its own ADR before being built. The role permission matrix below is a proposed starting point, not derived from any existing spec — five roles (Admin/Developer/Designer/Product Manager/Tester) were given from the original request; the specific capability grants are a best-effort default, flag anything that should change.
